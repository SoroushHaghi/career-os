# Standard Discovery Packet Template

Use this template when an older task/chat has accumulated a useful working standard that was never promoted into Career OS.

## Goal

Recover the repeatable operating rules learned in that chat without treating old outputs as canonical facts.

The source chat should return a structured packet with the sections below.

## Required packet

### 1. Scope
- What class of work did this chat handle?
- What artifacts were created?
- Which outputs were explicitly approved or treated as the best/latest baseline?

### 2. Artifact inventory
For each important artifact:
- artifact name/version;
- artifact type;
- status: draft / reviewed / user-approved / sent / published / unknown;
- what it is useful evidence for;
- what it must **not** be treated as evidence for.

### 3. User-confirmed durable preferences
List only preferences directly supported by the user's corrections/approvals.

For each:
- rule;
- evidence/example from the conversation;
- confidence: HIGH / MEDIUM / LOW;
- scope: global / CV / cover letter / application-specific / other.

### 4. Repeated successful patterns
Identify structures or methods that repeatedly produced accepted results.

For each:
- pattern;
- why it appears repeatable;
- supporting artifacts/turns;
- whether it should become a default.

### 5. Rejected patterns / anti-rules
Capture what the user explicitly rejected or repeatedly corrected.

For each:
- rejected behavior;
- preferred replacement;
- supporting evidence.

### 6. Content-selection rules
Include, where relevant:
- what belongs/does not belong;
- evidence thresholds;
- section inclusion/exclusion;
- ordering priorities;
- tailoring rules;
- claim-strength boundaries.

### 7. Writing/style rules
Include, where relevant:
- tone;
- sentence/bullet style;
- length;
- repetition policy;
- level of specificity;
- preferred terminology;
- phrases/patterns to avoid.

### 8. Layout/rendering rules
Include, where relevant:
- page target;
- hierarchy;
- spacing;
- typography;
- link behavior;
- photo/QR policy;
- file naming/versioning;
- mobile/ATS/readability rules.

### 9. Workflow
Reconstruct the actual successful step-by-step process from input to approved artifact.

Separate:
- required steps;
- optional steps;
- user approval gates;
- QA gates;
- external-action gates.

### 10. QA checklist
List the checks that were necessary before the user accepted an artifact.

### 11. Conflicts / evolution
Identify rules that changed over time.

For each:
- old rule;
- newer rule;
- evidence that the newer rule supersedes the old one;
- unresolved conflict if any.

### 12. Missing / unknown
State what cannot be recovered from the visible conversation/artifacts.

Do not guess.

### 13. Proposed promotion map
For each recovered rule, classify it as one of:
- reusable generic standard;
- user-specific durable preference;
- canonical fact/evidence;
- task-specific decision;
- raw/source artifact reference;
- unresolved / needs confirmation.

Do not write to Career OS from the source chat unless it already has the correct canonical write context. Return the packet for promotion by the owning Career OS workflow.
